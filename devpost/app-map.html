StepWise / a guide to the finished source

From notice to next action.

StepWise turns an administrative notice into a temporary checklist with inspectable source passages. The fictional sample works without a key. Optional live analysis reads a supplied document locally, then asks a configured service to organize its text.

This is a reference route, prepared from actual code on 26 September 2026. It records no completed learner exercise, edit, reflection, or approval.

How the optional live branch differs

lib/server/process-document.ts, anchor processLiveDocument, calls extractDocument before the provider. extract-document.ts and extraction-worker.ts own bounded PDF/OCR child processes. Text-bearing PDFs and direct English images are supported; unreadable PDF pages are refused.

lib/server/live-provider.ts, anchor OpenAICompatibleProvider.analyze, sends extracted segments and a contract to a configured /chat/completions service. It does not send the raw file or filename. validateAnalysisResult then checks the returned quotes against independently extracted segments. Provider retention still applies; a quote match does not establish correct interpretation.

There is no database, account, analytics, or persistent document store. The browser keeps answers/completion in React state; request resources and extraction processes are temporary. Real-provider quality has not been evaluated with credentials.

Three stops to follow in your editor

Run the app, choose Try the sample, then use these stable search anchors. Relative links open source files when supported by your browser; the paths also work in an editor.

  1. Start the request. Open components/stepwise-app.tsx and find StepWiseApp, submit, and resetSession. The sample button calls submit({ mode: "sample" }). The controller parses the returned contract, drops successful input and guards against an old response replacing a new session. The page entry is app/page.tsx, anchor HomePage.
  2. Find the trust boundary. Open app/api/analyze/route.ts, anchor POST. Sample mode calls processSample, which validates sampleResult. In lib/server/evidence.ts, find validateAnalysisResult and assertEvidence: authoritative sources must be supplied, source IDs must be unique, and each nonblank quote must exist in its referenced segment.
  3. Connect state to the visible next action. Open components/action-plan.tsx, anchor ActionPlan. Select Gathering documents: prioritizeActions maps the selected option to its action. Choose Mark complete: toggleComplete updates the local set and remaining/nextAction derive the count and next task. showEvidence opens EvidenceDrawer with the referenced source and quote.

A practice to reuse: specify what counts as evidence

The review exposed a result that could pair an unrelated upload with fabricated sample passages. The correction makes the server's extracted segments the authority, rather than allowing a model to provide its own proof. prd.md → Evidence and uncertainty states the intended behavior; tests/server/trust-regression.test.ts → rejects an unrelated upload paired with fabricated sample sources exercises the failure, and validateAnalysisResult enforces the boundary.

On another project, choose an observable promise, name who owns the underlying data, and test a plausible mismatch before trusting a plausible-looking result. Here the check proves quote provenance. It does not prove eligibility, interpretation, completeness, or professional correctness.
